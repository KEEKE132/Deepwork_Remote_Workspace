에이전트 간 통신
(Agent-to-Agent) 표준·기술 동향

서로 다른 사용자·프레임워크·벤더의 AI 에이전트가 안전하게 협업하는 방법. 에이전트 간 통신 표준(A2A, ANP, ACP, MCP, AGNTCY/SLIM)의 현황과 생태계 동향, 그리고 실무 적용 방안을 정리한다.

Executive Summary

한눈에 보는 요약

2026년 현재 에이전트 간 통신은 "표준화가 본격화"되는 단계다. 전송 수준 보안 메시징(SLIM), 에이전트 간 협업(A2A), 웹 기반 P2P 네트워크(ANP), 도구 연결(MCP)이 각자 역할을 명확히 하며 상호보완적으로 성장하고 있다.

5종주요 A2A 통신 표준·프로토콜
100+A2A 공식·커뮤니티 파트너 (AWS, IBM, Adobe, LangChain 등)
6+A2A 공식 SDK 언어 (Python·Go·Java·JS·.NET·Rust)
조직Agentic AI Foundation (A2A 합류), LF Projects (AGNTCY)

핵심 결론 3가지

  • 두 계층으로 나뉜다 — "메시지를 어떻게 주고받을지"(전송: SLIM, ANP)와 "무슨 의미의 협업인지"(의미: A2A 태스크/메시지)가 분리되어 상호보완적으로 발전 중.
  • 폴링은 여전히 기본이되, 표준이 push·SSE를 함께 정의 — 오프라인·단절 시나리오까지 포함한 수신 메커니즘(폴링/스트리밍/푸시 알림)이 각 스펙에 명시됨.
  • 표준화 기구·거버넌스가 자리잡는 중 — A2A는 2026-08-27부로 Agentic AI Foundation으로 이관, AGNTCY는 LF Projects 산하, ANP는 독립 오픈소스 커뮤니티로 운영.
Landscape

주요 표준·프로토콜 개요

에이전트 간 통신을 다루는 표준은 크게 5가지 축으로 정리된다. 각자의 목적·담당 계층·성숙도를 확인한다.

A2A (Agent2Agent)

소유: Agentic AI Foundation (2026.8 합류)

에이전트↔에이전트 협업·상호운용을 위한 공개 표준. Task/Message/Artifact 모델과 Agent Card(발견·능력·인증)를 정의. 폴링·SSE·푸시 알림 3가지 수신 방식 명시.

성숙: v1.0표준화 진행 중

ANP (Agent Network Protocol)

소유: agent-network-protocol (오픈소스)

"에이전트 인터넷의 HTTP" 지향. 연합(federated)·DID 기반 P2P 에이전트 네트워크. Agent DID, 발견, E2E 인스턴트 메시징(직접/그룹), 결제 프로토콜(AP2) 포함.

성숙: v1.1메타프로토콜 draft

ACP (Agent Client Protocol)

소유: CADE / agentclientprotocol

코드 에디터 ↔ 코딩 에이전트 연결 표준. 같은 머신(호스트) 내 클라이언트-에이전트 통신에 초점. JSON-RPC 기반, 상태 있는 세션.

안정: protocol v1IDE 도구

MCP (Model Context Protocol)

소유: 모델 컨텍스트 커뮤니티

에이전트↔도구·데이터·리소스 연결 표준. A2A와 상호보완적 ("도구는 MCP로, 동료 에이전트는 A2A로"). Claude·ChatGPT·VS Code 등 광범위 채택.

광범위 채택도구 연결

AGNTCY / SLIM

소유: LF Projects 산하 AGNTCY

에이전트 네트워크 전송 인프라. SLIM은 보안·저지연 메시징으로 그룹(방)·pub/sub·MLS 종단간 암호화 제공. OASF·Identity·Directory·SHADI로 확장.

IETF 표준화

OASF / Identity / Directory

소유: AGNTCY

에이전트의 스키마(OASF)·탈중앙 신원(Identity)·페더레이션 발견(Directory). 에이전트 생태계의 "디렉토리·ID" 계층.

Deep Dive

A2A와 ANP 깊게 보기

"숨겨진 메신저방(그룹 협업 방)" 관점에서 가장 관련 깊은 두 표준을 심층 분석한다.

A2A — 협업·작업 오케스트레이션

  • 에이전트 카드(Agent Card): 신원·능력·스킬·인증 방식의 JSON 메타데이터. 상대방이 "어떻게 대화할지"를 아는 진입점.
  • Task / Message / Artifact: 상태 있는 작업 단위, 턴 기반 대화, 파일·구조화 산출물. 멀티턴·병렬 팔로업·산출물 참조 지원.
  • 발견 3전략: well-known URI / 큐레이션 레지스트리 / 직접 설정·사설 발견(초대·URL) — "숨겨진 방"은 3번째 전략에 해당.
  • 수신 메커니즘: Request/Response(폴링) · SSE 스트리밍 · Push 알림(웹훅)으로 연결 끊김·장기작업 대응.
  • 보안: API Key·HTTP Auth·OAuth2·OIDC·상호 TLS 인증 스킴을 스펙에 포함. in-task 인가(사람 승인 게이트) 지원.

ANP — 연합형 P2P 네트워크

  • "에이전트 인터넷의 HTTP": 플랫폼 중심이 아닌 프로토콜 중심의 직접 연결 지향.
  • DID 기반 신원: did:wba 메서드, WNS 핸들(alice.example.com)로 해석, 키 로테이션 지원.
  • 인스턴트 메시징 9개 프로파일: 직접/그룹 메시징, E2EE(MLS), 첨부·대용량 객체, 페더레이션, 멘션·셀렉터 분리.
  • 그룹 거버넌스: group.create/invite/accept/join/add/remove/leave 등 명시적 제어 평면.
  • 제어/데이터 평면 분리: 메시지에 manifest만 싣고 객체는 별도 HTTP(S) 채널로 전송.

SLIM — 전송·암호화 인프라

  • 그룹(방) 기본 제공: 중재자(Moderator) 모델로 멤버 초대·제거. create-channel / add-participant.
  • MLS 종단간 암호화: 그룹 메시지에 대한 E2E 보안. 세션 상태 영속화로 오프라인·재접속 처리.
  • pub/sub·스트리밍: 다수 에이전트 구독에 유리. 데이터 플레인·컨트롤러·채널 매니저로 구성.
  • 표준화: IETF 드래프트 draft-mpsb-agntcy-slim 진행 중.
Trends

생태계 동향 5가지

표준 문서·기구 발표에서 관찰되는 최신 흐름을 정리한다.

① A2A, 범(凡)재단으로 공식 이관

2026-08-27, A2A가 Agentic AI Foundation에 합류. 벤더 중립적 거버넌스 확립. AWS·IBM·Adobe·Intuit·Kakao·LG CNS 등 100여 개 파트너가 참여.

② v1.0으로 성숙

A2A v1.0 스펙 공개로 명확성·구조 개선. SDK 공식 6개 언어 + 커뮤니티(Rust·Swift·Elixir·C++)까지 확장. 커뮤니티 주도 표준화 강조.

③ MCP의 광범위 채택

도구 연결 표준으로서 사실상 표준 위치. A2A는 "Build with ADK, equip with MCP, communicate with A2A"로 MCP와 상호보완을 공식화.

④ "인터넷 오브 에이전트(IoA)" 인프라 성숙

AGNTCY(SLIM·OASF·Identity·Directory·SHADI)가 LF Projects 산하에서 발견·신원·암호화·관측 인프라를 통합 제공.

⑤ 연합형 P2P 지향

ANP처럼 이메일·비트코인에 빗댄 분산형·연합형 접근이 등장. 중앙 허브 없이 도메인 간 직접 통신·결제(AP2)·DID 신원까지 포함하는 비전.

Recommendation

적용 방안·로드맵

"서로 다른 사람의 에이전트가 협업하는 숨겨진 메신저방" 구축 시나리오 기준으로 권장 조합을 제시한다.

권장 조합: 전송은 SLIM(혹은 ANP), 의미는 A2A. "방(채널·멤버십·E2E 암호화)"은 전송 계층에서, "무엇을 요청하고 무슨 결과를 주고받는지"(Task·Message·Artifact)는 A2A에서 처리한다. 사람 승인 게이트는 A2A의 in-task 인가를 활용한다.

공통 아키텍처

# 개별 PC 에이전트 ↔ (전송 계층) ↔ 허브 ↔ (전송 계층) ↔ 개별 PC 에이전트
사용자 A PC ── 에이전트 A (A2A 클라이언트 + SLIM 노드)
        │                         ▲
        ▼                         │
허브·방 서버 (SLIM Channel Manager + A2A 게이트웨이 + MLS 암호화)
        ▲                         │
        │                         ▼
사용자 B PC ── 에이전트 B (A2A 클라이언트 + SLIM 노드)

# 수신: 상시 구동 → SSE/pub-sub, 비상시 → 폴링 + A2A push(웹훅)

3단계 로드맵

  1. Phase 1 — PoC (상호운용 검증): A2A SDK로 에이전트 카드 발급 + Task 왕복. 허브 1대로 폴링/SSE 동작 확인.
  2. Phase 2 — 방 기능 (숨겨진 방): SLIM 그룹 채널(create-channel · add-participant)로 초대·멤버십·MLS E2E 암호화. 오프라인·재접속 처리.
  3. Phase 3 — 신원·관측·규모화: AGNTCY Identity·Directory·Observability(Eval) 접목. 승인 게이트·감사·발견·성능 평가 추가. 필요 시 ANP 페더레이션으로 확장.
